# 核心模板与写作契约集（Writer Packet & Contracts）

本文件包含「阶段一（调研提纯）」与「阶段二（独立干净上下文撰写）」交接所需的全部标准模板。无论宿主 Agent 采用哪种底层方式调用撰写模型，均必须严格遵守以下结构契约。

---

## 一、 `writer-packet.md` 标准简洁模板（模式一与模式二通用）

主会话完成搜索与原文精读后，必须将所有有效材料去噪提纯，按以下 4 个模块写入 `<run-dir>/writer-packet.md`：

```markdown
# Writer Packet（干净写作资料包）

## 1. 写作任务与读者定位
- **核心议题**：<一句话清晰界定本次报告要回答的中心问题>
- **目标读者与视角**：<如：关注技术、商业或人文演进的大众深度读者>
- **时效与语境基准**：<标明当前时间基准与核心语境>
- **文风与特殊要求**：<未指定时写“采用默认大众人文杂志讲述型写法，语言自然流动，避免列表堆砌”；若用户有明确文风/结构要求则在此写明>

## 2. 无序论点—证据地图（Unordered Argument Map）
> **写作契约**：以下论述单元为【无序集合】，仅用于约束成稿必须覆盖的论点、证据对应关系与张力边界。
> 撰写模型【严禁】将本表顺序当作章节目录，也【严禁】照抄单元 ID 或内部标签作为小标题。请先独立判断中心问题与最佳叙事主线，自主重排、合并或拆分论述单元，并独立拟定最契合文章气质的总标题与小标题。

- **[U-01]** 必选论点/待答问题：<用中性语言描述该单元要讲透的核心问题>
  - **支撑证据 IDs**：[S01], [S03]
  - **与其他单元的张力/关系**：<如：与 U-03 的乐观预期构成现实成本反差>
  - **事实风险与限定边界**：<如：仅在特定样本验证，不可外推为普适定律>

- **[U-02]** 必选论点/待答问题：...
  - **支撑证据 IDs**：[S02], [S04]
  - **与其他单元的张力/关系**：...
  - **事实风险与限定边界**：...

- **[U-Counter]** 反方校正与争议视角：...
  - **支撑证据 IDs**：[S05]
  - **事实风险与限定边界**：...

## 3. 提纯证据与原话摘录池（Purified Evidence Pool）
> **引用准则**：正文中出现的所有关键数字、日期、人物关系、直接引语和因果机制，必须严格源自下方证据池，并在文内标注 `[S01]` 等引用标记，文末附完整来源列表。

- **[S01]** 《来源标题》（作者/机构，发布日期，等级 A/B/C，URL）
  - **核心核实事实/数据**：<精炼列出已从原文核实的硬数据、时间点、案例细节与机制事实>
  - **关键原话/段落摘录**：<极具表现力的原话引语或精确段落内容>
  - **证据属性**：`direct`（直接事实） | `source_view`（特定作者观点） | `synthesis_premise`（综合推断前提）

- **[S02]** 《来源标题》（作者/机构，发布日期，等级 A/B/C，URL）
  - **核心核实事实/数据**：...
  - **关键原话/段落摘录**：...
  - **证据属性**：...

## 4. 事实禁区与不确定性说明（Guardrails & Uncertainties）
- **严禁混淆的边界**：<明确指出调研中发现容易被误传、夸大或张冠李戴的说法>
- **需降级表述的推断/类比**：<哪些跨领域连接或推演必须显式加上“有研究者认为”“可作类比”“尚存争议”等限定语>
- **已知材料缺口**：<若有未公开或无法核实的数据，要求在文中诚实交代而非猜测>
```

## 二、 阶段二：独立撰写模型的标准 System Prompt

当你启动独立干净上下文（空白 Subagent / 本地 MaGpie 网关 / 外部 API / 无状态 CLI）执行撰写时，使用以下系统提示词：

```text
你是一位顶级深度杂志主笔。你当前运行在独立的「纯净撰写阶段（Clean-Context Writing Stage）」。
你的全部事实依据仅限于下方提供的《Writer Packet（干净写作资料包）》。

【文风与排版准则】
除非资料包中另有明确指定，请务必使用地道中文，以报刊杂志、非学术、大众人文杂志、讲述型的写法去撰写报告。语言应当自然流动，善于用具体的人物截面、细节与认知冲突引入，用叙事逻辑推进段落，避免生硬的列表清单（bullet points）堆砌；图表需要控制出现频率（全篇最多在收束处用一张高密度对比表总结，或完全不用）；写作根据内容可以尽可能详细展现，字数不限制。使用规范的全角中文标点，不使用半角英文标点代替中文标点。

【叙事结构与防八股契约】
输入的「无序论点—证据地图」仅是无序的论点与证据集合，绝不是文章目录。不要沿用其行顺序、单元标签或研究素材措辞作为章节顺序、标题和固定表达。请先独立判断中心问题与最佳叙事主线，自主重排、合并或拆分论述单元，并拟定更适合成稿的总标题和小标题；同时覆盖全部必选论点，严格遵守证据池与事实禁区的边界，不得虚构未在资料包中提供的事实或数字。

【引用与输出要求】
在正文中引用具体事实、数据或原话时保留 `[S01]` 格式的角标，并在文章末尾附上对应的「参考与证据来源」列表（含标题与 URL）。直接输出完整的最终成稿 Markdown 正文，不要输出任何开场寒暄或过程说明。
```

## 三、 模式二（标准重度深研 Full Mode）附加过程工件简表

当用户显式开启 **模式二（Full Mode）** 时，除最终生成 `writer-packet.md` 与 `report.md` 外，在调研迭代期维护以下结构：

1. **`research-map.md`**：记录 `ID | 子问题 | 类型(required/optional/counterpoint) | 状态(open/partial/covered) | 关键 claims | 缺口`。
2. **`query-log.md`**：记录 `Round | Pack | Query ID | Query | 工具 | 结果数 | Source IDs | Insight Context ID | Context influence`。
3. **`sources.jsonl`**：每行记录 `source_id, url, title, grade(A/B/C/D), status(discovered/shortlisted/read/cited/verified), summary, limitations`。
4. **`insights.md`（滚动研究记忆）**：
   - 每轮必须产生 2–4 条带唯一 ID（`I-R1-01`）的洞察，并计算停止指标：
     - `coverage` = 已覆盖必选子问题 / 总必选子问题
     - `authority_gap` = 缺乏 A/B 级已读来源支撑的核心事实数
     - `open_conflicts` = 未处理的重大事实/观点冲突数
     - `high_value_delta` = 本轮新增且会改变结论或论点地图的高价值主张数
   - 当全部缺口清零且连续一轮 `high_value_delta = 0` 时，方可停止补搜，提纯生成 `writer-packet.md` 进入独立撰写。
5. **`citation-audit.md`（写后逐句蕴含审计）**：
   - 扫描 `report.md` 中的全部数字、日期、引语、人物关系与因果判断，逐条核对是否被原文真正蕴含（Entailment），标记 `direct | synthesis | editorial` 与 `supported | partially_supported | unsupported`。
